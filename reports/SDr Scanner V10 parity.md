# SDr Scanner V10 follows IC-R8600 workflows

V10 uses an IC-R8600-inspired face and places receiver menus inside the LCD. MODE sits beneath POWER. The face has a presets bank, two favourite banks, five assignable auxiliary dials, a main tuning dial and a dedicated volume knob with local mute. The radio uses the SDR’s nominal **100 kHz–1.75 GHz** tuning range. It supports analogue reception, RTTY and integrated clear digital reception, including conventional DMR and one configured DMR Tier III site. Verification covers browser controls and specific decoder fixtures. Live reception, tuning latency and field coverage on the installed SDR remain to be verified. ## The LCD adds the reference readout and two scope pages

The operating screen places **mode, passband and filter** at the upper left and active receiver options, recording status and clock on the top rail. Frequency and its keypad occupy the main readout, with VFO or memory group/channel at the right. The receiver feeds the tuning-error indicator and relative signal meter. The lower section shows an FFT trace and waterfall. **&lt;1&gt;** gives access to SPAN or EDGE, HOLD and CENT/FIX. **&lt;2&gt;** gives access to REF, SPEED and MARKER. The printed reference label is **EXPD/SET**. A tap expands the scope and a hold opens SCOPE SET. The browser also supports clicking a live scope point to tune and scrolling or dragging the virtual dials. [Icom manual, pp. 1-4–1-6 and 4-1–4-4](https://www.icomeurope.com/wp-content/uploads/2026/04/IC-R8600_ENG_IM_8.pdf#page=13) · [LCD and scope behavior](../web/v10.js)

**QUICK → Second Display** opens an LCD-only companion window at the fixed path `/lcd`. Refreshing the radio tab or the companion keeps them linked. Move it to the other monitor and use the browser’s fullscreen control. It mirrors the same browser panel’s display and menu state while the main tab remains open. Opening `/lcd` directly gives a read-only, PIN-free display of the active receiver’s tuning, scope and selected zones, including custom zone names. The companion takes no tuner assignment and plays no audio. Headless Chrome verified opening the companion, direct DMR tuning to 446.006250 MHz, the SCAN START menu, scope page changes and a 360 px mobile view. The separate physical HDMI monitor remains an installation test. [Companion and panel implementation](../web/v10.js)

## Grouped memories and scans use the receiver engine

The front-panel keys and dials cover power, tuning lock, frequency entry, VFO and memory selection, scan, priority and nested menus. The Monitor toggle is in the Dial B menu. Timer settings are under MENU → SET → Others. The memory store has **2,000 ordinary memories**, **50 program edge pairs** and an auto-write group. The same memory and scan controls can tune analogue or supported digital channels. Programmed and delta-frequency sweeps, auto memory write, memory scan, tagged selection, mode scan, temporary skip and priority use the backend. S.SCAN sweeps from the current frequency in either direction at the current tuning step. The preset keys open editable zones which can also be scanned. A permanent S skip-bank editor and native insert or move refinements remain outside the current editor. The timer includes sleep and one schedule with a stored channel reservation. The IC-R8600 documents three scheduled timers. ## Digital tests establish which receive paths work

| Mode | Implementation and verification | Remaining boundary |
|---|---|---|
| **DMR conventional** | Clear voice, colour code, slot, talkgroup and source ID when decoded. Memories support receive filters. HISTORY includes call and SMS metadata, with received message text and deletion in the SMS inbox. | Receive-only workflow. RF and SMS operation on the installed SDR remain field tests. |
| **DMR Tier III** | The production bridge followed a generated control and voice fixture from **430.012500 to 430.037500 MHz and back**, with **TG 100, source 1001 and CC 2**. Separate fixtures produced clear audio on both time slots. The end-to-end receiver worker delivered **69,120 bytes of 24 kHz PCM** to the audio stream and created a Discovery entry during the slot 1 test. The site profile supplies the control frequency and logical-channel map. Configure these in the LCD via MODE → DMR, then QUICK → DMR Tier III. | Live control acquisition and call latency, multi-site roaming and proprietary trunk variants remain unverified. One tuner leaves the control frequency while following a different traffic carrier. |
| **P25 Phase 1, D-STAR, NXDN-VN and dPMR** | The packaged DSD-neo path produced clear audio through the scanner’s decoder pipeline using C4FM P25, D-STAR, 4.8 kbps NXDN and dPMR fixtures. P25 NAC and NXDN RAN fixtures also verified filtering. | P25 CQPSK, D-STAR CSQL and dPMR CC/COM ID are outside the verified coverage. |
| **NXDN-N and DCR** | The MODE menu lists supported receive modes. | NXDN 9.6 kbps produced audio in the decoder’s direct IQ replay, but usable audio through the scanner’s discriminator path remains unverified. DCR requires a known signal fixture and identification path. |
| **Analogue and RTTY** | FM, WFM, AM, S-AM D/U/L, USB, LSB, CW/CW-R and FSK/FSK-R are integrated. FSK uses the ITA2 decoder and live text pages. | Weak-signal performance, all per-mode filter combinations and reference RTTY log formats remain outside the verified coverage. |

## The SET catalogue marks the hardware and software boundaries

| Reference branch | V10 coverage |
|---|---|
| **Tone Control** | Per-mode audio filtering and tone settings where the receive path supports them. FM tone search and CTCSS/DCS memory settings sit in FUNCTION. |
| **Function** | Live scan, tuning, beep, speech and lock controls. IF bandwidth, filter shape, twin PBT, AGC, CW pitch, notch, noise blanking and noise reduction act through the SDR DSP where offered. Proprietary Icom control variants and some DSP options are omitted from the LCD menus. |
| **Digital Set** | Linked decoder availability, supported digital squelch and receiver discovery/history. Icom-specific D-STAR auto-detect, NXDN fast-unmute and equivalent full history export remain gaps. |
| **Connectors** | Browser audio uses the SDR server’s audio stream. CI-V, electrical AF/IF outputs, the external meter and 10 MHz reference interfaces require separate hardware or protocols. |
| **Network** | The app serves receiver control over HTTP. The host owns network configuration. Icom network users, remote ports and RS-R8600 exclusive transport are omitted from the LCD menus. |
| **Display** | Browser backlight, mute dimming, display style, indicator brightness, memory name, RDS and decimal or hexadecimal P25 talkgroup IDs. The POWER screenshot setting saves a PNG. Icom-style localization, screen saver and display popups are omitted from the LCD menus. |
| **Time Set** | The display shows local and UTC. The host owns time, NTP and scheduled reception. |
| **SD Card** | Host storage holds squelch-triggered MP3 clips and discovery records. Recent playback and instant replay are available. Settings Backup saves and restores a versioned SDr Scanner JSON backup. Icom ICF files, removable-card management and Icom firmware update are omitted from the LCD menus. The full recording library and player options are outstanding. |
| **Others** | Version and app reset. Native cloning, BER hardware tests and touchscreen calibration are omitted from the LCD menus. |

The **1 MHz live scope** and **relative dBFS meter** reflect the SDR’s capture path. Icom specifies a wider scope and an absolute signal meter on its dedicated hardware. Scope Set on V10 adjusts averaging, max hold, reference level and waterfall display and speed. Icom waveform colour, video bandwidth and full peak-search settings are omitted from the LCD menus. Hardware antenna switching, P.AMP, ATT and IP+ also depend on the reference RF chain. V10’s tuner gain and DSP controls use the connected device’s supported capabilities. The recorder stores clips per reception and drops clips under two seconds. The Icom’s Always and unsplit recorder modes require separate semantics. [Icom manual, pp. 4-1–7-3, 11-1–11-10 and 14-1–14-2](https://www.icomeurope.com/wp-content/uploads/2026/04/IC-R8600_ENG_IM_8.pdf#page=25) · [V10 menu definitions](../web/v10-menus.js) · [Receiver DSP and scope](../receiver.py) · [Recorder](../recording.py)

The next evidence for operational parity is a receiver-host test with known transmissions. It should establish usable tuning across the SDR’s range, clear voice and SMS recall, Tier III acquisition and return times, scan timing during active reception, and second-monitor behavior over HDMI.
